# Security notes

Read this before installing. The plugin runs inside your Hermes process and
can see every Anthropic request, so it deserves scrutiny.

## What it never does

- **It never reads, stores, refreshes, or logs your credentials.** Hermes owns
  token resolution (Keychain / `~/.claude/.credentials.json` / env / pool).
  The plugin only inspects the `Authorization` header to decide *whether* to
  act, and never records or transmits it anywhere.
- **It never writes to `~/.claude*`.** No credential rotation, no refresh, no
  risk of logging out Claude Code.
- **It never phones home.** There is no telemetry, no analytics, no network
  call of its own. It only rewrites requests Hermes was already sending to
  `api.anthropic.com`.
- **It has no dependencies.** Nothing is pulled from PyPI at install time.

## What it reads

`~/.claude.json` (or `$CLAUDE_CONFIG_DIR/.claude.json`) for two values:

| Field | Use |
|---|---|
| `userID` | `device_id` in request metadata |
| `oauthAccount.accountUuid` | `account_uuid` in request metadata |

These are held **in memory only** and sent to Anthropic in the same request
metadata Claude Code itself sends. They are never copied to disk, printed, or
logged. Startup logging records only `identity=yes|no`.

If the file is absent or malformed, the plugin proceeds without metadata.

## Scope of the monkeypatch

Exactly one symbol is patched:

```
agent.anthropic_adapter.build_anthropic_client
```

The returned client's httpx transport is wrapped, and the wrapper rewrites a
request **only when all of these hold**:

1. method is `POST`
2. path ends with `/v1/messages`
3. host ends with `anthropic.com`
4. the `Authorization` header carries an `sk-ant-oat` OAuth token

Anything else — API-key requests, Bedrock, Azure, OpenAI, Gemini, local
models, every other provider — passes through byte-for-byte unmodified.
`uninstall()` restores the original function.

## Fail-open by design

If the envelope transform raises for any reason, the plugin logs a warning and
sends the **original** request. It cannot take Hermes down.

Understand the trade-off: a silent fallback means the request goes out with
Hermes' legacy envelope. On an account with extra usage disabled, Anthropic
rejects that loudly (HTTP 400), so the failure is visible rather than
expensive. On an account **with extra usage enabled, a fallback could bill to
extra usage instead of your plan.** If that matters to you, enable tracing and
watch for missing records.

## Optional accelerator

If the `xxhash` C module happens to be importable, it is used only after it
reproduces known vectors at import time. Any mismatch, or any import error,
falls back to the pure-Python implementation. The checksum can never silently
diverge.

## Tracing (opt-in, off by default)

`HERMES_BLACK_TRACE=/path/file.jsonl` records, per request:

```json
{"ts":"...","model":"...","cc_version":"2.1.224.f19","cch":"84159",
 "system_blocks":4,"tools":32,"has_metadata":true,"bytes":94798}
```

and non-identifying `anthropic-ratelimit-*` response headers.

Deliberately excluded: tokens, prompts, message content, tool arguments,
`anthropic-organization-id`, and request ids. A trace file is safe to attach
to a bug report. `cch` is a truncated hash of the request and is not
reversible.

## Verifying before you trust it

```sh
python3 -m unittest discover -s tests -v
```

23 tests, no network, no credentials, no Hermes required. The golden vectors
in `tests/vectors.json` were generated by executing pi-black's TypeScript
implementation, so any byte-level drift from the reference fails the suite.
